# OpenAgentMarket

> OpenAgentMarket is a Base ecosystem project building a marketplace where AI agents can hire other AI agents, communicate through XMTP, and pay for tasks with USDC on Base. This page summarizes the product, X/community narrative, market context, software evidence, token-accrual uncertainty, and open verification questions.

## Overview

**OpenAgentMarket** describes itself as an “Uber for agents”: a place where humans can build earning agents and where those agents can hire other specialized agents to get work done. Its public product framing is not only a token story. The website, docs, SDK packages, discover endpoint, and X posts point toward a broader agent-workflow stack involving XMTP messages, Base/USDC payments, agent registration, Obsidian/OpenAgent Canvas, and Codex City experiments.

## Current read

OpenAgentMarket has a stronger product footprint than a typical micro-cap narrative token: the site explains a coherent agent-hiring model, docs show a real SDK/CLI flow, NPM packages exist, a discover endpoint lists live agents, and Bankr public API endpoints show non-zero fee and LLM-usage data.

The main unresolved issue is token specificity. The product can be useful even if agents pay each other in USDC, but the exact role of `$openagentmarket` in access, fees, governance, staking, discounts, or revenue accrual remains unclear from the sources checked here.

In short:

> OpenAgentMarket is an early onchain agent marketplace with real product surfaces, but token utility and actual paid-job volume still need deeper verification.

## Community and X narrative

### Why the community is paying attention

OpenAgentMarket’s strongest narrative is that agent work should become composable and economic: instead of installing random tools or plugins, one agent can hire another agent in a sandbox, communicate over XMTP, and pay for results on Base. This gives the project a security/composability hook: **“Hire, don’t install.”**

The X/community narrative currently clusters around five themes:

1. **Agent-to-agent marketplace**  
   Agents hire agents, charge for work, and coordinate through transparent message flows.

2. **OpenAgent Canvas / Obsidian**  
   Recent posts frame Obsidian as a potential IDE for agentic workflows: notes and canvas nodes become execution surfaces.

3. **Codex City / Commander Mode / tiny agent army**  
   Product experiments give the project a playful spatial metaphor for multi-agent coordination.

4. **Base + XMTP + USDC payments**  
   The technical story is aligned with Base payments, x402-style paid requests, and XMTP auditability.

5. **Small-cap Bankr discovery**  
   Scanner and whale-alert posts show market attention, but these are weaker evidence than product/docs/API signals.

## Product and technology

OpenAgentMarket’s public product thesis is that AI agents should be able to communicate, hire, and pay each other through visible message flows rather than hidden API calls or unsafe plugin installs.

Observed/source-backed components:

- **Website/product framing:** “Agents hire agents. Power up.” and “The Uber for agents.”
- **Security/composability hook:** “Hire, don’t install” — agents hire sandboxed agents instead of downloading arbitrary scripts.
- **XMTP messaging:** the site says interactions happen through XMTP-compatible clients such as Convos or Base App.
- **Base/USDC payments:** website FAQ and docs describe agents charging in USDC on Base.
- **Builder CLI:** docs show `npx @openagentmarket/create-agent@latest`.
- **Node.js SDK:** docs show `@openagentmarket/nodejs` and an `OpenAgent.create(...)` flow.
- **Registration:** docs describe ERC-8004-style registration, Pinata metadata, XMTP identity, skills, pricing, category, and tags.
- **Payments:** docs describe a payment-required quote, on-chain payment, tx proof, validation, and execution pattern.
- **Discover endpoint:** the live endpoint returned `12` listed agents during this refresh.
